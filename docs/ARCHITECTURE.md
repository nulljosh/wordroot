# Architecture

Wordroot is a dictionary with etymology. Look up any word, follow its roots backward through Latin, Greek, Old English, all the way to Proto-Indo-European. Runs on web (static), iOS, macOS, and Android (via KMP). All platforms read etymologies and definitions live from English Wiktionary via REST. The app supports 12 interface languages (English, Spanish, French, German, Portuguese, Italian, Dutch, Russian, Japanese, Simplified Chinese, Korean, Arabic) and 30 word languages. A single i18n catalog drives string generation for every surface.

## How it runs

**Web:** User navigates to wordroot.heyitsmejosh.com. Static HTML+JS loads. User enters a word and picks its language. The app fetches from en.wiktionary.org/w/rest.php: the `pages/{title}` endpoint to get definition and etymology sections, and strips HTML tags to present text. Etymology sections are parsed for `{{inh|...}}`, `{{der|...}}`, and `{{bor|...}}` templates, which name the ancestor word and the ancient language it came from. The app chains lookups up the tree (each ancestor is itself looked up) until reaching a root or hitting the max chain depth. No backend; everything fetches Wiktionary directly.

**iOS/macOS:** App launches, initializes settings from `UserDefaults` (interface language, word language). SwiftUI views present the same lookup UI. Network calls go through URLSession directly to Wiktionary. macOS gets a larger window and column-based layout; iOS is portrait-only cards.

**Android/KMP:** Compose Multiplatform app wrapping the same network logic. Desktop packages as DEB, MSI, or DMG via Gradle.

**TUI:** SwiftPM executable takes a word as an argument, looks it up, and prints the etymology chain to stdout.

## Core library and tools

| File | What it owns |
|---|---|
| `src/lib/tools.js` | The canonical tool definitions. Exports `callTool()` to look up a word's definition and etymology on Wiktionary. Parses etymology templates (`inh`, `der`, `bor`), resolves language codes to Wiktionary section headings, strips HTML tags, validates word input (100 char max, no newlines/pipes that could inject wikitext), and chunks chains to prevent infinite recursion (max 10 ancestors). Both the REST API and MCP server call `callTool()` so they cannot drift. |

## I18n and build scripts

| File | What it owns |
|---|---|
| `i18n/strings.json` | The single source of truth for every translated string in the app. 12 interface languages and 30 word languages, organized by key. Adding a string here means writing it in all 12 locales or not at all (a half-filled key falls back to English silently). Never edit `web/i18n.js`, `landing/i18n.js`, or `ios/Sources/Localized.swift` directly; they are generated from this file. |
| `scripts/gen-i18n.py` | Reads `i18n/strings.json` and generates `web/i18n.js`, `landing/i18n.js`, and `ios/Sources/Localized.swift`. Run after editing the string catalog. `--check` verifies that generated files are current (fails the build if stale). |
| `scripts/build-site.sh` | Build script for the web landing page. Calls `scripts/gen-i18n.py --check` to ensure the i18n bundles are current, failing if they're stale. Inlines the app into device frame HTML. |
| `scripts/test-web.mjs` | Web app tests. Verifies i18n generation, string substitution, and word lookup against fixture Wiktionary responses. |

## Data pipeline

Note: The data pipeline is not currently shipped. These scripts prepare to parse Wiktionary dumps into the SQLite database that future versions would use for offline lookups and advanced features (etymology trees, collections). The web app and current native apps read Wiktionary live via REST; the pipeline waits for offline/tree support to become needed.

| File | What it owns |
|---|---|
| `pipeline/parse.py` | (Not yet shipped.) Parses Wiktionary XML dumps into etymologies and definitions. Outputs `wordroot.sqlite` with `words` and `edges` tables. Supports multiple languages via `--lang` flag. Run `python3 pipeline/parse.py` to build English, or `--lang de` for German. stdlib only, no external dependencies. |
| `pipeline/test_parse.py` | (Not yet shipped.) Test suite for the parser. Verifies correct extraction of etymology templates from wikitext, language section scoping, and edge-chain construction. |

## Cloudflare Workers

| File | What it owns |
|---|---|
| `functions/api/[[route]].js` | REST API for word lookup. `GET /api/lookup?word=...&lang=...` calls `callTool()` from `src/lib/tools.js`. Returns JSON with definition and etymology chain. Adds `User-Agent` headers that Wikimedia prefers. Bypasses CORS restrictions on direct Wiktionary requests (the browser blocks cross-origin requests, but a Worker can make them). |
| `functions/mcp.js` | Model Context Protocol server. Registers a `lookup` tool that agents can call. Same implementation as the REST API, calls `callTool()` so the two cannot drift. |

## External services

- **English Wiktionary:** `en.wiktionary.org/w/rest.php/v1/pages/{title}`. Returns definition and full page wikitext. Etymology parsing scans for `===Etymology===` sections and extracts `{{inh|...}}`, `{{der|...}}`, `{{bor|...}}` template chains.
- **Other language editions:** `{lang}.wiktionary.org/w/rest.php/v1/pages/{title}` for definitions only. If a reader's edition doesn't exist or doesn't have a definition, falls back to English. |

## Gotchas

- **Etymology source:** Always reads etymologies from en.wiktionary.org regardless of interface language, because it is the only edition whose template markup (`inh`, `der`, `bor`) the parser understands. Other editions use different markup.
- **Definition fallback:** Tries the reader's own language edition first, then English. If an edition returns a 404, it is retired for the session (not retried per lookup). English is the always-available backstop.
- **Language sections:** The word language selects which `==Language==` section to read on the English page, not which site to fetch. `chat` in French returns Old French etymology and an English definition (from en.wiktionary.org).
- **Template injection:** Word input is validated strictly: no newlines, pipes, braces, or characters over 100 in length. These would be injection vectors into the wikitext the app parses.
- **Chain depth:** Max 10 ancestors to prevent infinite loops on malformed data. Cycles cannot happen because Wiktionary's `inh` templates always name an older language.
- **String concatenation:** Never build output sentences by concatenating translated fragments. Word order differs across the 12 languages. Use placeholder substitution instead (`{name}`), or keep the sentence structure in the source string.
- **i18n consistency:** `i18n/strings.json` is the only place a string is written. Generated files are never edited by hand. Running `scripts/build-site.sh` or `scripts/gen-i18n.py --check` verifies they are current.
